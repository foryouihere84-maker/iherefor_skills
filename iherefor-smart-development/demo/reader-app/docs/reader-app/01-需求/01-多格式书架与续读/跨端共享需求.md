## 1. 共享范围

### 1.1 纳入共享（两端必须一致）

| 类别 | 共享内容 | 为什么必须一致 | 不一致的后果 |
|---|---|---|---|
| 业务语义 | 导入（格式校验 / sourceUri 去重）、书架（importedAt 降序）、阅读（按格式分派渲染）、续读（进度持久化）、删除（记录与进度一并移除） | 两端是同一个产品，用户可换端使用；语义分叉即等于两个产品 | 同一本书在两端表现不同（如一端去重一端不去重） |
| 领域规则 / 不变量 | `领域模型.md` 的 `V1`~`V7` 全部 7 条（格式不可变 / sourceUri 唯一 / 进度一对一 / 定位与格式兼容 / 越界回退 / 删除不悬挂 / 列表降序） | 不变量是正确性底线，非平台相关 | 数据出现悬挂或不可读状态，且两端修复方式不同 |
| 数据契约 | `Book` / `ReadingProgress` / `Chapter` / `ParsedBook` 四实体的**跨端维度**（见第 4 节） | 两端读写同一批数据；字段名分叉会导致序列化不互通 | 换端后读不出自己写入的书 |
| 接口签名 | 导入 / 列表 / 删除 / 保存进度 / 解析等 10 项能力（见第 3 节） | 两端共用同一份用例语义；方法名分叉会让「同一能力」在两端叫法不同 | 跨端评审与对账无法逐条比对 |
| 枚举取值 | `BookFormat`（epub/pdf/txt）、`LocatorType`（chapter/page）的线格式取值与未知值处理（见第 5 节） | 枚举取值是写入数据的内容，分叉即数据不兼容 | 一端写入的格式取值另一端不认识 |
| 错误语义 | 7 类失败的触发条件与用户可见文案（见第 7 节） | 失败体验属产品一致性的一部分 | 同一操作在两端得到不同提示 |
| 单位 / 时区 / 精度口径 | 时间点（UTC epoch 毫秒）、索引基准（从 0 起）、集合排序（importedAt 降序）（见第 6 节） | 口径不统一必然出 Bug —— 跨端 Bug 高发区不是逻辑而是口径 | 进度错位、排序抖动、时间显示偏差 |

### 1.2 明确不共享（平台专属，允许分叉）

| 类别 | iOS 侧做法 | Android 侧做法 | 允许分叉的理由 |
|---|---|---|---|
| UI 实现 | SwiftUI（`LibraryView` / `ReaderView`） | Jetpack Compose（`MainActivity` / `ReaderScreen`） | 平台 UI 框架客观不同 |
| 平台能力 / 系统 API | `fileImporter` + `UTType`；文件路径 URL；`Data(contentsOf:)`；PDFKit | `ACTION_OPEN_DOCUMENT` + SAF；content URI；`contentResolver.openInputStream`；PdfRenderer | 文件访问与 PDF 渲染是平台私有能力，无跨端共性 |
| 构建与工具链 | xcodegen + Xcode | Gradle | 平台工具链客观不同 |
| 测试栈 | XCTest / Swift Testing | JUnit + MockK + Turbine | 见 `config/mobile-tdd.json` |
| 依赖选型 | 系统 `Compression` 框架（EPUB ZIP）、PDFKit | `ZipInputStream`、PdfRenderer | EPUB/TXT 自研、PDF 用系统 API；两端实现路径不同但对外行为一致 |
| 资源与性能策略 | 主线程 + `Data` 全量读入 | 协程 + `ByteArray` 全量读入 | 首版数据量小，未做流式；**对外行为须符合共享契约** |

命名规则、双端字面映射、缩写白名单、禁止用词。

### 2.1 命名总则（本项目实测结果）

基线规则集全文与出处见 `references/跨端共享.md`。**本批次实际用到并已核验的条目**：

| 编号 | 规则 | 本项目核验结果 |
|---|---|---|
| N1 | 类型 / 协议名 UpperCamelCase；字段、方法、参数用 lowerCamelCase | ✅ 全部符合（`Book` / `importBook` / `sourceUri`） |
| N3 | 字段名必须是名词，不是动词 | ✅ `format` / `progress` / `title` 均为名词 |
| N4 | 布尔字段省略 `is` 前缀 | 本批次无布尔字段 —— 不涉及 |
| N5 | 集合用复数、单值用单数 | ✅ `repository.books()` 返回 `[Book]` / `List<Book>`；单值处用 `book` |
| N6 | 字段名不得含介词 | ✅ 无 `reasonForError` 类命名 |
| N8 | 广为人知的缩写优先用缩写 | ✅ 用 `id` 而非 `identifier`、用 `uri` 而非 `uniformResourceIdentifier` |
| N11 | 通用资源标识用 `uri`；仅表示网址才用 `url` | ✅ 用 `sourceUri` / `coverUri`（两端一致，未出现 `sourceUrl`） |
| N13 | 字段名不得与所在类型同名 | ✅ 无 `Book.book` 类命名 |
| N15 | 禁止无意义词 `Manager` / `Helper` / `Util` / `Wrapper` / `Impl` | ✅ 未出现（内存实现命名为 `InMemoryLibraryRepository`，语义明确） |
| M1 | 方法名 = 动词 + 名词 | ✅ `importBook` / `removeBook` / `saveProgress` / `readAndParse` |
| M2 | 有副作用用祈使动词；无副作用用名词短语 | ✅ 有副作用 `importBook`（祈使）；纯函数 `books()`（名词短语） |
| M4 | 变异 / 非变异成对方法用后缀区分 | ✅ Swift `clamp(within:pages:)`（变异）/ Kotlin `clamped(withinChapters:withinPages:)`（返回副本） |
| M6 | 布尔返回的方法读作断言 | ✅ `isSupported` / `isProgressCompatible` |

**本项目覆盖登记**（只登记**偏离基线**的条目）：

| 编号 | 覆盖内容 | 理由 | 影响面（哪些字段/接口） |
|---|---|---|---|
| M3 | 工厂方法不以 `make` 开头（`fromExtension` / `ParsedBook(chapters:)`） | `fromExtension` 是**类型转换构造**而非"创建新对象"（Kotlin/Java 生态惯例为 `from*` / `of*`）；Swift 侧 `ParsedBook(chapters:)` 是结构体成员初始化器（语言机制，不可命名） | I7 格式识别、`ParsedBook` 构造 |

### 2.2 禁止使用的同义词

**同一个概念禁止出现第二个名字。** 本表是 `领域模型.md` 术语表的**反例面**——左列沿用其权威名，右列是禁止写法。
两端任一位置（代码 / 文档 / 测试 / UI 文案）出现禁用词即为漂移，交付门「一致性对账」须报出。

| 权威名（引自领域模型术语表） | 禁止使用的同义词 | 扫检范围 |
|---|---|---|
| `Book` | bookItem / document / publication / item | 两端 `domain/` |
| `Library` | shelf / collection / bookshelf | 两端 `domain/` / `data/` |
| `importBook` | add / insert / load / ingest | 两端 viewmodel / usecase |
| `Reader` | viewer / renderer | 两端 UI 层 |
| `ReadingProgress` | position / bookmark / cursor / location | 两端 `domain/` |
| `BookFormat` | FileType / Format / BookType | 两端 `domain/` |
| `Metadata` | meta / info / attributes | 两端 `domain/` |
| `sourceUri` | sourcePath / fileUrl / originUri | 两端 `domain/` |
| `ParsedBook` | content / document / bookContent | 两端 `domain/` |
| `LocatorType` | ProgressType / PositionKind | 两端 `domain/` |
| `LibraryRepository` | BookStore / StorageManager | 两端 `data/` |

> **扫描结论（本批次实测）**：两端 `domain/` `data/` 目录未发现上述禁用词（抽检 T1~T5，见第 10 节 K1）。

### 2.3 双端字面映射

**线格式名是权威拼写；两端代码属性名是它的语言派生形式。凡两端字面不同者必须在此登记。未登记的差异一律视为缺陷。**

| 权威名 | 线格式（序列化名） | iOS（Swift）字面 | Android（Kotlin）字面 | 差异原因 |
|---|---|---|---|---|
| `id` | `id` | `id: String`（`UUID().uuidString`，**大写**） | `id: String`（`UUID.randomUUID().toString()`，**小写**） | 平台 UUID API 大小写不同 —— **已知差异，见下方 D1** |
| `importedAt` | `importedAt` | `importedAt: Date` | `importedAt: Long`（epoch 毫秒） | Swift 用 `Date`、Kotlin 用毫秒时间戳；**语义等价**（见第 6 节时间口径） |
| `updatedAt` | `updatedAt` | `updatedAt: Date` | `updatedAt: Long` | 同上 |
| `ParsedBook.chapters` | —（仅内存） | `chapters: [Chapter]` | `chapters: List<Chapter>` | 集合类型按语言惯例；语义等价 |
| `add`（仓库方法） | — | `add(_ book: Book)`（省略首参标签） | `add(book: Book)`（具名参数） | Swift 惯例省略首参标签；**语义等价** |
| 格式识别方法 | — | `SharedRules.detectFormat(fromExtension:)` | `BookFormat.fromExtension(ext:)` | **位置与命名不同**：Swift 在 `SharedRules`、Kotlin 在 `BookFormat` 伴生对象。语义等价，见下方 D2 |
| `parse`（解析方法） | — | `BookReaderService.parse(format:data:)` 实例方法，入参 `Data` | `BookReaderService.Companion.parse(format:data:)` 伴生对象方法，入参 `ByteArray` | Swift 需实例持 parser 表；Kotlin 用伴生对象做无状态分派。**调用姿势不同，语义等价** |
| `parse`（解析器协议） | — | `BookParser.parse(data: Data)` | `BookParser.parse(data: ByteArray)` | 二进制载体类型按语言惯例（`Data` / `ByteArray`） |

> **D1 标识大小写（待收敛）**：两端 UUID 字符串大小写不同。当前不影响可达路径——去重键是 `sourceUri` 而非 `id`，
> 且首版未落盘。**一旦引入持久化或跨端数据交换，此差异会导致同一本书在两端 id 不相等**，故列为待收敛项：
> 建议两端统一 `lowercase` 后再落盘（对齐 RFC 4122 惯例以小写表示）。
>
> **D2 格式识别方法位置不同（已接受）**：语义完全一致（均为「扩展名小写 + trim → 枚举 / nil」），
> 但方法名与归属不同。按 3.3 的 M1 基线，同一能力应同名——**已接受为平台惯例差异**（Kotlin 的 `companion object`
> 工厂更符合语言习惯），登记于此以免后续被误判为漂移。

### 2.4 缩写白名单

**不在白名单内的缩写一律视为非法**（避免两端各自造缩写）。

| 缩写 | 全称 | Swift 写法 | Kotlin 写法 | 备注 |
|---|---|---|---|---|
| id | identifier | `id` | `id` | 两端一致 |
| uri | Uniform Resource Identifier | `sourceUri` / `coverUri` | `sourceUri` / `coverUri` | 两端一致；**未使用** `url`（本场景均为通用 URI） |
| pdf | Portable Document Format | `.pdf`（枚举取值）/ `ParserError` 中字面 | `PDF` | 枚举取值见 5.1 |
| epub | Electronic Publication | `.epub` | `EPUB` | 同上 |
| txt | plain text | `.txt` | `TXT` | 同上 |

> 注：`Uri`（3 字母）在 Swift 侧按「缩写当普通词处理」写成 `Uri` 而非 `URI`，与 Kotlin 的 `Uri` 恰好一致——
> 故本批次**未出现** `coverURL` / `coverUrl` 这类大小写分歧。这是基线规则在真实场景下的一种「自然对齐」。

### 2.5 禁止用词与保留词

| 词 | 类型 | 原因 | 替代 |
|---|---|---|---|
| `Manager` / `Helper` / `Util` / `Wrapper` | 禁止 | 无信息量（Kotlin 基线 + 本项目纪律） | 用具体语义命名（`LibraryRepository` / `SharedRules`） |
| `Data` | 保留 | 与 Swift 平台类型 `Data` 冲突 | 命名时避开；本项目用 `ParsedBook` 承载解析结果 |
| `URL` | 慎用 | 本场景为通用 URI（文件路径 / content URI 均有），用 `URL` 会窄化语义 | `sourceUri` / `coverUri` |
| `index` | 允用（局部） | 章节序号字段名为 `index`，语义明确 | 实体级不冲突，保留 |

## 3. 共享接口规范

两端对同一能力的**调用方式与语义必须一致**：方法名相同、参数含义相同、成功与失败的结果形状相同。
实现各写各的（Swift 一份、Kotlin 一份），但**契约只有一份，就是本节**。实体与参数的类型含义沿用 `领域模型.md`。

### 3.1 接口总览

| 编号 | 能力 | 权威方法名 | 输入 | 输出 | 失败语义 | 双端是否同构实现 |
|---|---|---|---|---|---|---|
| I1 | 列出书架 | `books()` | — | `Book` 列表（importedAt 降序，`V7`） | 无 | 同构（同名同序） |
| I2 | 导入书籍 | `importBook(ext:sourceUri:title:)` | 扩展名、源定位、书名 | 成功空 / 失败错误文案 | `不支持的格式`（E1）/ `已存在`（E2） | 同构（同名同文案） |
| I3 | 移除书籍 | `removeBook(id:)` | 书籍 id | 无 | 无（幂等） | 同构 |
| I4 | 保存进度 | `saveProgress(bookId:progress:)` | 书籍 id、进度 | 无（不兼容时静默忽略） | 无（静默丢弃，见 7.1 E7） | 同构 |
| I5 | 按格式解析 | `parse(format:data:)` | 格式、字节 | `ParsedBook` | `文件为空`（E3）/ `PDF 非重排格式`（E5） | 仅语义同构（调用姿势不同，见 2.3） |
| I6 | 读取并解析 | `readAndParse(book:)` | `Book` | `ParsedBook` | 读取失败（E6）/ `文件为空`（E3）/ `PDF 非重排格式`（E5） | 仅语义同构（平台文件 API 不同） |
| I7 | 识别格式 | `detectFormat(fromExtension:)` / `fromExtension(ext:)` | 扩展名字符串 | `BookFormat` / 空 | 无（返回空表示不支持） | 仅语义同构（见 2.3 D2） |
| I8 | 进度↔格式兼容校验 | `isProgressCompatible(format:progress:)` | 格式、进度 | 布尔 | 无 | 同构 |
| I9 | 按源定位去重 | `findDuplicate(sourceUri:in:)` | 源定位、书籍列表 | 已存在的 `Book` / 空 | 无 | 同构 |
| I10 | 仓库写操作 | `add` / `remove(id:)` / `updateProgress(bookId:progress:)` | — | — | 无 | 同构（仅首参标签差异） |

### 3.2 接口明细

> 签名用跨语言中立写法：`方法名(参数名: 类型口径) -> 返回`，不写成某一种语言。

#### I2 `importBook(ext:sourceUri:title:)`

| 项 | 内容 |
|---|---|
| 权威方法名 | `importBook(ext:sourceUri:title:)` |
| 双端字面 | iOS: `func importBook(ext: String, sourceUri: String, title: String) -> String?` ／ Android: `fun importBook(ext: String, sourceUri: String, title: String): String?` |
| 签名（中立） | `importBook(ext: 字符串, sourceUri: 字符串, title: 字符串) -> 错误文案或空` |
| 输入 | `ext` = 文件扩展名（可含点 / 空白，实现侧负责归一化）；`sourceUri` = 源文件定位；`title` = 书名 |
| 输出 / 成功形状 | 成功返回 `null`；失败返回用户可见错误文案字符串（**不用异常**） |
| 失败与错误 | `不支持的格式`（E1）、`已存在`（E2） |
| 前置条件 | 调用方已拿到系统文件选择器返回的 URI / 路径 |
| 后置条件 / 不变量 | 成功时书架新增一本书，`id` 为新生成标识，`format` 由 `ext` 判定且此后不可变（`V1`）；同一 `sourceUri` 不产生第二条记录（`V2`） |
| 幂等性 | **非幂等但对重复输入幂等**：同一 `sourceUri` 重复调用返回 `已存在`，不新增记录 |
| 副作用 | 写入仓库；不触发网络；UI 由调用方自行刷新 |
| 并发 / 重入 | 未做并发保护（首版单线程 UI 调用）；并发调用可能产生重复记录 —— **已知限制** |
| 超时 / 取消 | 不涉及（同步、无网络） |

#### I5 `parse(format:data:)`

| 项 | 内容 |
|---|---|
| 权威方法名 | `parse(format:data:)` |
| 双端字面 | iOS: `BookReaderService.parse(format: BookFormat, data: Data) throws -> ParsedBook`（实例方法） ／ Android: `BookReaderService.Companion.parse(format: BookFormat, data: ByteArray): ParsedBook`（伴生对象） |

## 6. 跨端一致性铁律

| 维度 | 本项目统一口径 | 禁止的做法 | 实现位置 |
|---|---|---|---|
| 时间点 | **epoch 毫秒**（UTC 纪元）；Swift 用 `Date`（等价表示为毫秒）、Kotlin 用 `Long` | 本地时间、不带时区的格式化字符串 | `Book.importedAt` / `ReadingProgress.updatedAt` |
| 时长 | 本批次不涉及 | — | — |
| 数值精度 | 本批次不涉及（无小数运算） | — | — |
| 单位 | 本批次不涉及（无物理量） | — | — |
| 百分比与进度 | 进度用**序号**（章节号 / 页码），不用百分比；序号**从 0 起**（0 = 第一章 / 第一页） | 一端 0 起、一端 1 起 | `chapterIndex` / `pageIndex` |
| 文本编码 | TXT 解码顺序：**UTF-8 优先 → GB18030 兜底**（两端一致） | 只支持 UTF-8 | `TxtParser.decode` |
| 文本比较 | 去重键 `sourceUri` 用**精确字符串比较（大小写敏感）**；不做路径归一化 | 一端归一化一端不归一化 | `findDuplicate`（`V2`） |
| 空值语义 | 三态：字段不存在 / 存在但为空 / 存在且有值。本批次用**可选三态**表达 | 用 `""` / `0` / `-1` 冒充「无」 | 各可选字段 |
| 集合顺序 | 书架 = `importedAt` **降序**；章节 = `index` **升序** | 依赖未声明的实现顺序 | `InMemoryLibraryRepository.books`（`V7`） |
| 标识符 | UUID 字符串；**当前大小写两端不同**（待收敛，见 2.3 D1） | 假设两端 id 可直接字符串相等比较 | `Book.id` |
| 数值边界 | 进度序号 < 0 或 ≥ 上限 → **回退到 0** | 抛错 / 崩溃 / 静默保留越界值 | `clamp` / `clamped`（`V5`） |

> **TXT 解码的已知边界差异（待收敛）**：两端均为 UTF-8 → GB18030，但**最终兜底不同**——
> Swift 还有一层有损 UTF-8 解码（`String(decoding:as:)`，总能出内容、不抛错）；
> Kotlin 在 GB18030 也失败时会抛出未捕获异常。**建议后续统一为「有损解码 + 不抛错」**（与两端「绝不因编码问题打不开书」的产品意图一致）。

> **本表是交付门「一致性对账」的核验清单来源之一**：每一行都能在两端代码里找到对应实现。
> 标注「待收敛」的三处（标识大小写、TXT 兜底、未知枚举值）为本表新增的核验维度，
> 首版对账（`一致性对账-00-首版.md`）尚未覆盖此维度，故在此明示，不留隐藏落差。

## 7. 失败与错误语义

**同一失败，两端必须给出同一个标识与同一套用户可见行为。** 这是跨端体验一致性的核心。

### 7.1 错误清单

| 错误标识 | 触发条件 | 双端错误字面 | 对用户可见 | 用户可见文案 | 可重试 | 处理要求 |
|---|---|---|---|---|---|---|
| E1 | 扩展名不属于 epub/pdf/txt | iOS: 返回 `"不支持的格式"`<br>Kotlin: 返回 `"不支持的格式"` | 是 | **不支持的格式** | 否 | **一致 ✅**：拒绝导入，不创建记录，UI 提示 |
| E2 | `sourceUri` 已存在 | iOS: 返回 `"已存在"`<br>Kotlin: 返回 `"已存在"` | 是 | **已存在** | 否 | **一致 ✅**：不重复添加，UI 提示 |
| E3 | 文件为空（0 字节，或切分后无章节） | iOS: `ParserError.emptyFile` → `"文件为空"`<br>Kotlin: `ParserException("文件为空")` | 是 | **文件为空** | 否 | **文案一致 ✅ / 载体不同**：Swift 用枚举错误、Kotlin 用异常类 |
| E4 | 无法识别的编码 | iOS: `ParserError.unsupportedEncoding` → `"无法识别的编码"`<br>Kotlin: **无此分支**（GB18030 兜底几乎必成功） | 是（iOS） | 无法识别的编码 | 否 | **两端不对称 ⚠️**：iOS 有该错误分支，Kotlin 没有 |
| E5 | 对 PDF 调用解析（PDF 无章节流） | iOS: `ParserError.pdfNotStreamed` = `unsupportedEncoding` → 展示 **"无法识别的编码"**<br>Kotlin: `ParserException("PDF 非重排格式")` | 是 | iOS「无法识别的编码」/ Kotlin「PDF 非重排格式」 | 否 | **文案不一致 ⚠️（待收敛）**：见下 |
| E6 | 读取源文件失败 | iOS: 抛 `ParserError.emptyFile` → `"文件为空"`<br>Kotlin: `ParserException("无法读取文件")` | 是 | iOS「文件为空」/ Kotlin「无法读取文件」 | 视情况 | **文案不一致 ⚠️（待收敛）**：见下 |
| E7 | 进度与格式不兼容 | **两端均静默忽略，不报错** | 否 | — | — | 静默是刻意设计（防写入非法进度，`V4`）；但**不落日志**，排查困难 —— 建议补日志 |

| 编号 | 规则 | 本项目状态 |
|---|---|---|
| R1 | 错误传播方式两端一致 | ⚠️ **部分不一致**：I2/I3/I4 用「返回错误字符串」（两端一致 ✅）；I5/I6 用「抛错」（两端一致 ✅）。但**错误的载体类型不同**：Swift 用 `ParserError` 枚举、Kotlin 用 `ParserException` 类。语义等价，登记于此 |

> 2. **E6 读取失败的文案**：iOS 复用「文件为空」，Kotlin 用「无法读取文件」—— 同一失败两种说法。
> 3. **R2 日志缺失**：E7 静默路径无日志。
>
> 这三项均属「跨端共享需求」新纳入的核验维度（首版对账未覆盖），**记为待收敛项**，
> 建议在下一批次或本批次补充实施时一并处理（最小改法：iOS 为 PDF 场景建独立 error case，文案对齐 Kotlin）。

## 9. 分叉点

以下内容**两端允许或必须不同**，是落地层各自实现的部分：

- **UI 实现**：iOS 用 SwiftUI（`LibraryView` / `ReaderView`），Android 用 Jetpack Compose（`MainActivity` / `ReaderScreen`），视觉细节各自实现。
- **平台文件访问 API**：iOS 用 `fileImporter` / `UTType` 与文件路径；Android 用 `ACTION_OPEN_DOCUMENT` / SAF 与 content URI。
- **格式解析实现**：
  - EPUB 解压：iOS 用系统 `Compression` 框架，Android 用 `ZipInputStream`（均为自研最小实现）。
  - PDF 渲染：iOS 用 `PDFKit`（系统内置），Android 用 `PdfRenderer`（系统内置）。
- **构建方式**：iOS 用 xcodegen + Xcode，Android 用 Gradle。
- **测试栈**：iOS 用 XCTest / Swift Testing，Android 用 JUnit + MockK + Turbine。

> 分叉不等于放任：以上分叉均**未导致第 1.1 节任一共享项出现行为差异**——唯一的例外是
> 第 6 节标注的 TXT 解码最终兜底（属分叉引发的行为差异），已登记为待收敛项。
