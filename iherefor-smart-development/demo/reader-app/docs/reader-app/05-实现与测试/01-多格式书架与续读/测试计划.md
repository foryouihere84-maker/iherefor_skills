## 1. 测试栈

- **iOS**：XCTest（Swift 5.9，部署目标 iOS 17.0 可用 Swift Testing，但为稳定采用经典 XCTest 断言）。
- **Android**：JUnit4 + MockK（mock 外部依赖）+ kotlinx-coroutines-test `runTest`。Turbine 已配但本功能领域层为无 Flow 纯函数为主，必要时用于 ViewModel Flow 测试。

## 2. seam 位置

测在「领域纯函数 + ViewModel/用例层」，不动 UI 层（`ui_layer: off_by_default`）：

- **领域纯函数（两端一致的核心 seam）**：`SharedRules` 里的格式校验、进度↔格式兼容、越界回退、`sourceUri` 去重——**无外部依赖，纯函数直测**。
- **解析器（BookParser 实现）**：`TxtParser` / `EpubParser` 的「输入字节 → ParsedBook」逻辑，若涉及文件 I/O 则把字节流作为输入注入（不直接测文件系统）。
- **仓库/用例（依赖注入 seam）**：`LibraryRepository` 通过协议/接口注入到 ViewModel，测试时用内存实现替代真实持久化。
- **解析分派（用例层 seam）**：`BookReaderService` 按 `BookFormat` 分派 parser，输入字节流、输出 `ParsedBook`——纯分派逻辑直测（2026-09-17 修复阅读器内容未填充时新增）。
- **外部依赖 mock**：Android 的 content URI 解析、iOS 的文件读取，在 ViewModel 测试中用注入的接口 mock，不真碰系统文件。

## 3. should 用例

| should 用例 | Mock | 断言 |
|---|---|---|
| shouldRejectUnsupportedFormat | 无（纯函数） | 传入 `"mobi"` → 返回不支持格式，不产生 Book |
| shouldClassifyPdfAsPageLocator | 无 | `format=pdf` ⇒ `locatorType=page` |
| shouldClassifyEpubAsChapterLocator | 无 | `format∈{epub,txt}` ⇒ `locatorType=chapter` |
| shouldClampProgressToStartOnOutOfRange | 无 | 越界 `chapterIndex`/`pageIndex` → 回退 0 |
| shouldDedupeBySourceUri | 无 | 同 `sourceUri` 导入两次 → 仅一条 Book |
| shouldSplitTxtIntoChapters | 无 | 多段 TXT → 正确章节序列 |
| shouldRejectEmptyFile | 无 | 空 TXT/损坏 EPUB → 显式失败，不入书架 |
| shouldFallbackEncodingForNonUtf8 | 无 | GBK 字节 → 正确解码 |
| shouldRecoverProgressOnOpen | 注入内存仓库 | 打开书 → 恢复上次 progress |
| shouldRemoveBookAndProgressOnDelete | 注入内存仓库 | 删除 → 记录与进度一并移除、源文件不动 |
| shouldDispatchTxtToTxtParser | 无（BookReaderService） | TXT 字节流 → 分派到 TxtParser 出章节 |
| shouldDispatchEpubToEpubParser | 无（BookReaderService） | 真实 EPUB（stored ZIP）→ 分派到 EpubParser 出章节 |
| shouldThrowForPdf | 无（BookReaderService） | PDF 字节流 → 抛「非重排格式」错误 |

> 两端各自实现同语义测试（命名对齐 `should` 前缀，语言级差异允许）。测试代码落在各工程 `Tests`/`test` 目录，由阶段 6.1 双端编译+测试门兜底。
