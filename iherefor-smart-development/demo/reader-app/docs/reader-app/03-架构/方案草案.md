## 1. 变更概述

采用**方案 3（混合方案）**：以「自研 EPUB 最小解析 + 纯函数 TXT 解析 + 系统内置 PDF 渲染」为骨架，用 `BookParser` 协议作为可替换 seam，锚定一套跨端共享契约（`Book`/`Chapter`/`ReadingProgress`/`BookFormat`/`LocatorType`，语义对齐 Readium Locator），两端落地层各自用平台 API 实现文件导入与持久化。核心是「共享契约 + 两端分叉、零/低第三方依赖、seam 可测」。

## 2. 落地分叉

### 共享层（两端一致，先定）

- 领域语义与跨端契约（见 `01-需求/01-多格式书架与续读/领域模型.md`、`01-需求/01-多格式书架与续读/跨端共享需求.md`）；这些契约的工程落点见 `03-架构/跨端共享层.md`。
- 纯函数领域规则：格式合法性校验、进度↔格式兼容校验、越界回退、`sourceUri` 去重、TXT 章节切分、编码探测（UTF-8 优先）。

### iOS 侧（SwiftUI + Swift）

- 文件导入：`fileImporter` + `allowedContentTypes`（`UTType.epub`/`UTType.pdf`/`UTType.plainText`）。
- EPUB 解析：自研最小 `EpubParser`（解 ZIP → 解析 OPF/NCX → 抽 XHTML 章节纯文本），实现 `BookParser` 协议。
- TXT 解析：`TxtParser` 纯函数切分章节。
- PDF 渲染：`PDFKit`（`PDFDocument`/`PDFView`），进度用 `pageIndex`。
- 持久化：进度与书架元数据写本地（首版轻量序列化文件，可升级 SwiftData）。
- 测试：XCTest / Swift Testing，测领域纯函数 + ViewModel。

### Android 侧（Kotlin + Jetpack Compose）

- 文件导入：SAF `ACTION_OPEN_DOCUMENT` + content URI + `takePersistableUriPermission`。
- EPUB 解析：自研最小 `EpubParser`（解 ZIP → 解析 OPF/NCX → 抽章节纯文本），实现 `BookParser` 接口。
- TXT 解析：`TxtParser` 纯函数切分章节。
- PDF 渲染：`PdfRenderer`（`Page#render()` 到位图），进度用 `pageIndex`。
- 持久化：进度与书架元数据写本地（首版轻量序列化，可升级 Room）。
- 测试：JUnit + MockK + Turbine，测领域纯函数 + ViewModel。

### 升级预留点

- EPUB 解析引擎：`BookParser` 协议隔离，未来可整体替换为 Readium Swift/Kotlin Toolkit，业务层与共享契约不动。
