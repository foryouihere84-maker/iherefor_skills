## 1. 硬约束

- **平台基线**：iOS 部署目标 iOS 17.0（SwiftUI + Swift 5.9）；Android minSdk 24 / compileSdk 36 / targetSdk 36，Kotlin 1.9 + AGP 8.5（脚手架已定）。
- **格式范围**：仅 EPUB / PDF / TXT，其余一律拒绝导入（对应 `BookFormat` 枚举三值）。
- **PDF 用系统内置**：iOS 必须用 `PDFKit`，Android 必须用 `PdfRenderer`，**不得**引入第三方 PDF 渲染依赖（facts 已证系统内置即可，且降低依赖风险）。
- **文件访问走官方 API**：iOS `fileImporter` + `UTType`；Android SAF `ACTION_OPEN_DOCUMENT` + content URI（含 `takePersistableUriPermission` 持久授权）。
- **编译硬门槛**：iOS（xcodebuild）与 Android（gradlew）分别编译 0 error，才可交付。
- **seam 可测**：领域层 / 用例 / ViewModel 必测；依赖经接口注入，禁止在被测对象内 `new` 具体依赖（Constitution 规定）。
- **共享契约先行**：领域语义（`01-需求/<批次>/领域模型.md`）与跨端约束（`01-需求/<批次>/跨端共享需求.md`）在阶段 1 定好，两端落地层各自引用，不得两端独立建模；本阶段只决定这些契约的**工程落点**（见 `跨端共享层.md`）。

## 2. 软约束

- **EPUB 解析库选型**：Readium 是双端事实标准（Swift Toolkit / Kotlin Toolkit），但体积较大、接入复杂度高。若「最小闭环 + 可控体积」优先，可先以「自研最小 EPUB 解析（解 ZIP + 解析 OPF/NCX/章节 XHTML 抽纯文本）」起步，Readium 作为后续升级项。这是可权衡项，在方案对比中给出立场。
- **本地持久化**：iOS 可 SwiftData/Core Data，Android 可 Room；但为控制范围，最小闭环可先用内存仓储 + 轻量序列化（进度持久化到文件）。可权衡。
- **TXT 编码探测**：优先 UTF-8，必要时兜底常见编码（GBK），探测逻辑放共享层纯函数。
- **UI 复杂度克制**：阅读器首版只做「重排文本（EPUB/TXT）+ 按页（PDF）」，不做复杂排版定制。
