## 1. 页面清单

| 屏 id | 屏名 | 对应故事 | 用途（一句话） |
|---|---|---|---|
| `书架-加载中` | 书架（加载中） | US-2 | 首次进入书架、正在读取本地书籍时的中态 |
| `书架-空态` | 书架（空） | US-2 | 一条书都没有时，引导用户去导入 |
| `书架-有数据` | 书架（有书） | US-2、US-5 | 书架主列表：书名/作者/格式/进度，可打开与删除 |
| `阅读器-正文` | 阅读器（正文） | US-3、US-4 | 按格式分派的阅读界面，承载续读 |
| `导入-格式被拒` | 导入（格式被拒） | US-1 | 用户选了不支持的格式时，明确拒绝并引导重选 |

> **倒查核对**：US-1~US-5 五条故事均有屏承载（US-1 的拒绝路径在 `导入-格式被拒`，正常导入路径由系统文件选择器承担、
> 不在本原型内画；US-4 续读表现为 `阅读器-正文` 与 `书架-有数据` 上的进度标记）。

## 2. 关键交互

| 从 | 动作 | 到 | 说明 |
|---|---|---|---|
| `书架-空态` | 点「导入书籍」 | `导入-格式被拒` | 原型内以拒绝态演示导入分支（正常分支走系统文件选择器，不在原型内） |
| `书架-有数据` | 点任一书籍行 / 封面 | `阅读器-正文` | 进入阅读器，按该书格式分派渲染 |
| `书架-有数据` | 点底栏「书架」 | `书架-有数据` | 底栏常驻，当前页高亮 |
| `阅读器-正文` | 点顶栏「‹ 书架」（iOS）/ 返回（Android） | 上一屏 | 返回书架，不退出应用 |
| `导入-格式被拒` | 点「重新选择文件」 | `书架-有数据` | 重新发起导入 |
| `导入-格式被拒` | 点「返回书架」/ 顶栏返回 | `书架-有数据` | 放弃本次导入 |
| 任意屏 | 工具条切 iOS / Android | 同屏 | 切换平台视觉语言，屏清单与状态不变 |

| 项 | iOS | Android |

## 5. 设计取舍

- **保真度档位**：**V2 视觉稿**（本阶段默认）。无 V0 灰盒局部。
- **变体决策**：`书架-有数据` 出 **2 个结构互斥变体**（上限 5，此处 2 个足够）——
  - **变体 A（列表式）**：信息密度高，一行内同时给出书名/作者/格式/进度，适合"已有很多书、要快速扫"。
  - **变体 B（封面网格）**：封面优先，视觉冲击强，适合"书少、以封面辨识"。
  - **胜出 A**：阅读应用的主诉求是**续读**（US-4），进度是核心信息；网格布局为放封面牺牲了进度与作者的可见性，
    与"快速找到上次读的书"冲突。B 的封面视觉保留为后续可选项（可在设置里切换视图）。
  - 落选变体 B 留在 `原型图.html` 中**折叠保留**（便于评审对比与后续复活），不删除文件、不合并进 A。
- **结构取舍**：**不画导入流程的中间屏**。正常导入由系统文件选择器（iOS `fileImporter` / Android SAF）接管，
  是平台能力而非本应用界面；原型只画"被拒绝"这个**应用需要自己负责**的分支，避免画无意义的系统弹窗假图。
- **跨端一致性**：页面清单、状态集合与文案两端一致；顶部/底部导航形态、主操作入口（Android 用 FAB）、圆角与阴影按平台分叉。
  不追求"两端长得一模一样"——那会让两端都用别扭的系统惯用法。
- **越界回退的呈现**：不弹窗、不提示，静默回退到起点（与 `01-需求/01-多格式书架与续读/领域模型.md` 的不变量一致：
  "越界视为无效进度，回退到起点"）。原型里以「未开始」形态体现，避免用户感知到数据异常。

## 6. 走查记录

| 屏 id | 覆盖的故事 / 场景 | 覆盖状态 | 结论 |
|---|---|---|---|
| `书架-加载中` | US-2 浏览书架（首次进入） | 加载中（骨架屏） | 通过 |
| `书架-空态` | US-2 浏览书架（无数据） | 空态 | 通过 |
| `书架-有数据` | US-2 浏览书架、US-5 删除、US-1 重复导入去重 | 有数据、极值（超长截断） | 通过 |
| `阅读器-正文` | US-3 打开并阅读、US-4 续读 | 有数据、越界回退（以「未开始」体现） | 通过 |
| `导入-格式被拒` | US-1 导入不支持格式 | 错误 / 拒绝 | 通过 |

**走查四问**：

1. **每屏都能倒查到故事吗？** 能。五屏对应 US-1~US-5，映射见第 1 节表格与倒查核对。
2. **每屏的状态覆盖齐了吗？** 齐。空态/加载中/有数据/错误拒绝/边界越界/极值六类均有承载屏，
   不适用的项已注明理由（见第 3 节）。
3. **跨端一致的部分画出来了吗？** 画了。同一 HTML 内含 iOS / Android 两套视觉语言，工具条可切换，
   屏清单与状态集合两端共用；差异项列在第 4.4 节。
4. **有没有想当然画出来、与 Spec 冲突的屏？** 无。特别核对了三处易错点：
   - 导入流程**只画拒绝分支**，未虚构系统文件选择器界面；
   - 越界回退**不画弹窗**，与领域模型「静默回退」的不变量一致；
   - 书架排序按**导入时间降序**（与 `用户故事-00-多格式书架与续读.md` US-2 验收场景一致），原型中三本书的顺序即按此排。

**结论**：**通过**。提请闸门 p 确认页面清单、视觉观感与屏间流程。
