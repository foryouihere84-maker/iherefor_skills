## 2. 命名规范

命名规则（`N*` / `M*` 编号）、双端字面映射、缩写白名单、禁止用词。
**术语定义与权威名在 `领域模型.md` 的术语表**，本节只承载**跨端命名纪律**。

### 2.1 命名总则

| 编号 | 规则 | 反例 → 正例 | 依据 |
|---|---|---|---|
| N1 | 类型 / 协议名用 UpperCamelCase；字段、方法、参数、局部变量用 lowerCamelCase | `book_format` → `bookFormat` | Swift / Kotlin |
| N2 | 常量（编译期常量）用 SCREAMING_SNAKE_CASE | `maxRetryCount` → `MAX_RETRY_COUNT` | Kotlin |
| N3 | **字段名必须是名词，不得是动词或动作意图** | `disable` → `disabled` / `collectItems` → `collectedItems` | AIP-140 |
| N4 | 布尔字段省略 `is` 前缀；与保留字冲突时才加 | `isDisabled` → `disabled`；`new` → `isNew` | AIP-140 |
| N5 | 集合 / 数组用复数，单值用单数 | `bookList` → `books`；`books`（单值）→ `book` | AIP-140 |
| N6 | 字段名不得含介词（with / for / at / by） | `reasonForError` → `errorReason` | AIP-140 |
| N7 | 形容词前置 | `itemsCollected` → `collectedItems` | AIP-140 |
| N8 | 广为人知的缩写优先用缩写，不得展开成全称 | `configuration` → `config`；`identifier` → `id`；`specification` → `spec` | AIP-140 |

| N10 | 时间点字段以 `Time` 收尾并统一为绝对时间（见第 6 节） | `createdAt` / `createDate` → `createTime` | AIP-142 |
| N11 | 通用资源标识用 `uri`；仅表示网址才用 `url` | `link` → `uri` / `url` | AIP-140 |
| N12 | 人类可读名称用 `displayName`（不要求唯一）；正式名用 `title` | `name`（歧义）→ `displayName` | AIP-140 |

### 5.2 枚举演进规则

| 编号 | 规则 | 说明 |
|---|---|---|
| E1 | 取值一经发布不得改语义、不得复用 | 删除的取值永久保留为「已废弃」，不得让编号或字面值被重新占用 |
| E2 | 新增取值须评估老版本行为 | 老版本读到新取值必须走 5.1 的「未知值处理」，不得崩溃 |
| E3 | 每个枚举须标注「冻结」或「可增长」 | 冻结 = 不再新增；可增长 = 允许追加，且说明追加节奏上限 |
| E4 | 有限取值集合不得用字符串或布尔硬编码 | 需要枚举化；但若业界已有广泛采用的标准表示，直接用标准表示 |
| E5 | 双端字面必须成对登记 | 不允许一端有取值、另一端未登记 |

## 6. 跨端一致性铁律

跨端 Bug 的高发区不是逻辑，而是**口径**。以下维度必须逐条定死，不允许「到时候看」。
违者由交付门「一致性对账」报出。

| 维度 | 统一口径 | 禁止的做法 | 说明 |
|---|---|---|---|
| 时间点 | | 本地时间且不带时区 | 时区、存储格式、精度（秒 / 毫秒）三件事都要写 |
| 时长 | | 两端各用一套单位 | |
| 数值精度 | | 浮点直接比较相等 | 小数位数、舍入规则、比较方式 |
| 单位 | | 同一字段两端不同量纲 | 字节 / KB / MB；公制 / 英制 |
| 百分比与进度 | | 一端 0~1、一端 0~100 | 区间、端点是否含、如何表达「未开始 / 已完成」 |
| 文本编码 | | 各用各的默认编码 | 编码、规范化形式（NFC / NFD）、解码失败兜底 |
| 文本比较 | | 用语言默认比较规则排序 | 大小写敏感性、地域 / collation、空白与全半角 |

| 数值边界 | | 溢出与极值行为未定义 | 最大值 / 最小值 / 越界回退规则 |

## 7. 失败与错误语义

**同一失败，两端必须给出同一个标识与同一套用户可见行为。** 这是跨端体验一致性的核心。

### 7.1 错误清单

| 错误标识 | 触发条件 | 双端错误字面 | 对用户可见 | 用户可见文案 | 可重试 | 处理要求 |
|---|---|---|---|---|---|---|
| E1 | | | 是 / 否 | | 是 / 否 | |

### 7.2 错误约定

| 编号 | 规则 | 说明 |
|---|---|---|
| R1 | 错误传播方式两端一致 | 抛出 / 返回结果对象 / 回调——统一一种，不要一端抛一端返回码 |
| R2 | 用户不可见的错误不得静默吞掉 | 必须落日志，日志标识用第 7.1 节的错误标识 |
| R3 | 用户可见文案由本表统一 | 两端可因平台语气微调，但含义与可操作建议必须一致 |
| R4 | 可重试性必须显式标注 | 由错误类型决定，不由调用方猜 |
| R5 | 错误标识一经发布不得改语义 | 同 5.2 的 E1 |

## 8. 兼容性与演进

共享契约是**跨端、跨版本**的公共资产，改动成本远高于单端代码。本节规定「谁能改、怎么改」。

| 编号 | 场景 | 允许的改法 | 必须同步的内容 |
|---|---|---|---|
| C1 | 新增字段 | 直接加，自带默认值（F4） | `领域模型.md` + 本表 + 两端代码 + 一致性对账 |
| C2 | 新增枚举取值 | 允许追加，评估 E2 | `领域模型.md` 第 4 节 + 本文件第 5 节 + 两端代码 |
| C3 | 改字段类型 / 单位 / 语义 | **不得原地改**，走新字段 | 新批次 + 两份文件 + 两端代码 + 受影响的全部文档 |
| C4 | 删除字段 / 取值 | 先标记废弃，保留至少一个批次后再移除 | 两份文件 + 两端代码 + 交付报告 |
| C5 | 架构层（`03-架构/`）随之变更 | 走全项目同步流程 | 文档 + 代码 + **所有活跃批次**的相关产物 |

> **本文件是批次内收敛型产物**：本批次内可原地更新；但**已交付批次的契约变更会波及后续批次**，
> 必须回到「批次清单」评估影响面，不得只在本批次内改完就宣布完成。跨批次的契约改动由交付门 `一致性对账` 卡住。
