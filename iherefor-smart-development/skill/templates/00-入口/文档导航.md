### 3.1 批次内产物路径规则

`<批次>` 即 `NN-<需求名>`（如 `01-阅读进度续读`）：

| 阶段 | 批次内产物 | 类型 |
|---|---|---|
| `01-需求/<批次>/` | `需求-NN-<短名>.md`、`用户故事-NN-<短名>.md` | 追加型 |
| | `领域模型.md`、`跨端共享需求.md` | 收敛型 |
| `02-原型/<批次>/` | `原型说明.md`、`原型图.html` | 收敛型 |
| `04-落地计划/<批次>/` | `变更清单-NN-<短名>.md` | 追加型 |
| | `架构审计.md`、`回滚方案.md`、`任务拆分.md` | 收敛型 |
| `05-实现与测试/<批次>/` | `测试计划.md` | 收敛型 |
| `06-交付/<批次>/` | `编译报告-NN-<短名>.md`、`审查报告-NN-<短名>.md`、`一致性对账-NN-<短名>.md`、`交付报告-NN-<短名>.md` | 追加型 |

- **追加型（批次内）**：本批次的第 NN 版，每次修订**新建下一个编号**，历史不可变。
- **收敛型（批次内）**：表达**本批次结束时的**当前真相，批次内原地更新；**非首批次开工时应从上一批次同名文件继承**再演进。

## 4. 主线读取顺序

新接手者按此顺序建立全局认知：

1. 本文（导航）→ 看第 3 节确定**当前批次**
2. `03-架构/方案草案.md` + `03-架构/跨端共享层.md`（**架构基线，全局共享**）
3. 进当前批次：`01-需求/<批次>/需求-*.md`（**按序号从小到大全部读**）→ `领域模型.md`
4. `02-原型/<批次>/原型说明.md` + `原型图.html`
5. `04-落地计划/<批次>/变更清单-*.md`（按序号全部读）→ `任务拆分.md`
6. `05-实现与测试/<批次>/测试计划.md`

## 5. 子 agent 分派口径

给子 agent 分派任务时使用以下格式：

```text
任务：<任务编号 - 名称>
批次：<NN-需求名>

必读：
1. docs/<feature>/00-入口/文档导航.md
2. docs/<feature>/03-架构/方案草案.md（架构基线，全局共享）
3. docs/<feature>/01-需求/<批次>/ 下全部 需求-*.md（必须全读，需求是追加累加的）
4. docs/<feature>/02-原型/<批次>/原型说明.md（涉及界面时必读，配套 原型图.html）
5. docs/<feature>/04-落地计划/<批次>/ 下最新 变更清单-*.md
6. 对应拆分产物

边界：
- 只处理被分配任务，且只动分配批次。
- 不改动闸门已确认的契约；不改动 `03-架构/`（架构改动须走全项目同步流程）。
- 不改动任何已编号的追加型产物（历史不可变）；需要修正就新建下一个编号。
- 不改动任何已冻结的历史批次；需要变更就走新批次。
- 如发现产物与本文冲突，先停下报告。
```
