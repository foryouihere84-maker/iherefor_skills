# 跨端共享层规范

当需求同时要 iOS 与 Android 两端落地时，本文件约束「什么必须共享、什么必须分叉」。

## 核心原则

**共享的是事实与契约，不是代码。** 两端语言/框架不同，不可能（也不应）共享源码；
共享的是「不会因平台而变」的那部分，落地层各自实现并守住同一份契约。

## 必须共享（单一事实源）

1. **需求与用户故事**：actor / feature / benefit 两端完全一致。同一份 spec，一次确认，两端共用。
2. **领域模型**：实体、值对象、状态机的语义定义一致。命名、字段含义、不变量在两端的领域层**等价**（不是字节级相同，而是语义一致）。
3. **数据契约**：API 请求/响应结构、本地存储 schema、跨端交互的字段类型与默认值必须一致。
   一处改，两端同步（这是「共享层」最硬的约束）。
4. **边界与规则**：输入校验规则、业务不变量、错误码语义，两端一致。

## 必须分叉（平台各自落地）

1. **UI 与技术栈**：iOS 用 SwiftUI/UIKit，Android 用 Compose/View；布局、生命周期、导航各自实现。
2. **平台能力接入**：网络库、数据库 ORM、依赖注入框架、权限申请、推送等走各自平台惯用法。
3. **测试栈**：见 `config/mobile-tdd.json` 的 ios_defaults / android_defaults。

## 落地产物

- 阶段 2 结束前必须产出**共享层文档**：领域模型、数据契约、不变量清单，作为两端开发共同的 spec 源。
- 两端落地代码各自独立，但**必须能通过同一份共享层文档做到语义对齐**（字段名、边界规则可交叉核对）。

## 反例（禁止）

- 两端各自写一份不同的领域模型，字段名/语义漂移。
- API 契约只在某一端写死，另一端「照着感觉」重造一份。
- 把「两端都要」当成「同一流程跑两遍、互不引用」。
