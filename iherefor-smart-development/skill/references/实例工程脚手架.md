# 实例工程脚手架（验证 / 教学 / 起步用）

当用户说「帮我建一个实例工程」「新增一个 demo 工程」或要验证本 skill 闭环时，按此快速起两端最小可编译空壳。
目标是**编译能过的最小骨架**，不含业务逻辑——业务在阶段 4 用 TDD 长出来。

## iOS 最小工程（推荐用 xcodegen）

本机有 `xcodegen` 时（`which xcodegen`），用 `project.yml` 声明式生成 `.xcodeproj`，**不要手写 project.pbxproj**（易错）。

```
ios/
├── project.yml              # xcodegen 声明
├── SubTracker/              # 源码（AppDelegate + 一个占位 VC）
└── SubTrackerTests/         # XCTest 目标 + 一个 sanity 测试
```

`project.yml` 要点：`GENERATE_INFOPLIST_FILE: YES`、`CODE_SIGNING_ALLOWED: NO`（模拟器编译免签名）。

```bash
cd ios && xcodegen generate
xcodebuild -project SubTracker.xcodeproj -scheme SubTracker \
  -destination 'platform=iOS Simulator,name=<已装模拟器>' build
```

**语言决定测试栈**：Swift 工程配 XCTest/Swift Testing；Objective-C 工程配 XCTest（ObjC 风格），见 `references/iOS测试约定.md`。

**ObjC 测试 target 坑**：test target 的 `sources` 必须**同时纳入领域源码目录**（否则链接报 `_OBJC_CLASS_$_XXX undefined`）。见 `references/iOS测试约定.md` 的「符号链接坑」。

## Android 最小工程（Gradle wrapper 自举）

```
android/
├── settings.gradle          # 含阿里云镜像（见下）
├── build.gradle             # AGP 8.5 + Kotlin 1.9 + Compose BOM
├── gradle.properties        # 必须 android.useAndroidX=true（遗漏会 checkDebugAarMetadata 失败）
├── local.properties         # sdk.dir=~/Library/Android/sdk
├── gradle/wrapper/ + gradlew
└── app/ (MainActivity.kt + AndroidManifest + themes.xml + test/)
```

**三条实测坑（本机踩过）**：

1. **`android.useAndroidX=true` 必须写进 `gradle.properties`**。漏了会报
   `checkDebugAarMetadata FAILED: Configuration contains AndroidX dependencies, but android.useAndroidX is not enabled`。
2. **`local.properties` 写 `sdk.dir` 指向 SDK**；`ANDROID_HOME` 环境变量未设也能编译（靠 local.properties）。
3. **网络受限时 maven.apache.org 的 jar 会 TLS 握手失败**（如 `kotlinx-coroutines-core-jvm`）。
   解法：在 `settings.gradle` 的 `pluginManagement.repositories` 与 `dependencyResolutionManagement.repositories`
   **最前面加阿里云镜像**再放 google()/mavenCentral() 兜底：
   ```groovy
   maven { url 'https://maven.aliyun.com/repository/google' }
   maven { url 'https://maven.aliyun.com/repository/central' }
   maven { url 'https://maven.aliyun.com/repository/gradle-plugin' }
   ```

## 自举 wrapper（无全局 gradle 时）

机器无 `gradle` CLI 但 `~/.gradle/wrapper/dists/` 有缓存时，直接用缓存的 gradle 生成 wrapper：

```bash
GRADLE_HOME="$HOME/.gradle/wrapper/dists/gradle-8.9-bin/<hash>/gradle-8.9"
"$GRADLE_HOME/bin/gradle" wrapper --gradle-version 8.9
```

## 验证标准

两端各自 `build` 成功（iOS=BUILD SUCCEEDED / Android=BUILD SUCCESSFUL）即骨架就绪，可进入阶段 1。

## 启动模拟器（验收/演示用）

### iOS（simctl）

```bash
xcrun simctl boot "iPhone 17"         # 或其它已装模拟器名
open -a Simulator
xcrun simctl install "iPhone 17" <path>/SubTracker.app
xcrun simctl launch "iPhone 17" com.iherefor.subtracker
```

### Android（emulator，实测坑）

**坑：后台启动 emulator 时不要用 `| head` / `| tail` 管道。** emulator 是长驻进程，管道 buffer 满或关闭会触发
SIGPIPE 把它带崩——表现是日志打印到一半、`adb devices` 里设备永远不出现（`offline` 甚至无设备）。正确做法：
重定向到日志文件，不接管道：

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
# ✅ 正确：nohup + 重定向到文件，无管道
nohup "$ANDROID_HOME/emulator/emulator" -avd <AVD名> -no-snapshot -no-audio -no-boot-anim \
  > /tmp/emulator.log 2>&1 &
# ❌ 错误：emulator ... | head -40   （会 SIGPIPE 带崩进程）
```

启动后等设备上线 + boot 完成：

```bash
adb wait-for-device
# 轮询 boot_completed
for i in $(seq 1 60); do
  [ "$(adb shell getprop sys.boot_completed 2>/dev/null | tr -d '\r')" = "1" ] && break
  sleep 3
done
adb install -r <path>/app-debug.apk
adb shell am start -n <package>/.MainActivity
```

**先列 AVD**：`avdmanager list avd`（在 `cmdline-tools/<ver>/bin/`）确认 AVD 名与 ABI（arm64 模拟器需 Apple Silicon）。
