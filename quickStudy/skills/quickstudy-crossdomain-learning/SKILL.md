# quickStudy: 跨领域知识速学与回顾

按本 Skill 执行一次“输入理解 -> 核心知识卡 -> 深挖 -> 回顾 -> 导出”的完整学习流程。

## 0. 目标

用户输入可以是问题、关键词、或短句。你需要在最少轮次内提供：

1. 可快速掌握的首屏核心认知（固定 6 段）
2. 可持续深入的双入口深挖（编号 + 自然语言）
3. 明确争议/不确定标注
4. 可导出的学习结果与学习过程摘要表

## 0.5 规范优先级（必须遵守）

1. 本文件是实现与验收的唯一规范源。
2. 与 README/示例/设计文档冲突时，以本文件为准。
3. 先判意图，再进入对应分支；禁止跳过意图判定。

## 1. 强约束（必须遵守）

1. 知识分支首屏必须覆盖 6 段（允许轻微重排，不允许漏段）。
2. `clarificationBudget = 1`：首次实质回答前，最多只问 1 个澄清问题（意图或范围二选一）。
3. 深挖必须增量，禁止纯复读首屏。
4. 争议点必须显式标注“不确定/常见争议”。
5. 结论发生修订时，必须输出：`更新结论：...；原因：...`。
6. 用户触发导出时，必须导出：
   - 知识结果（首屏 + 深挖 + 修订轨迹）
   - 学习过程摘要表（非全量对话，按时间顺序）
7. 问题求解分支禁止输出知识深挖菜单（1-5）。

## 2. 会话状态（每轮维护）

维护以下会话状态（可隐式维护，不需要每轮都显示）：

- `topic`: 原始主题文本
- `topicSlug`: 路径安全主题标识（用于导出文件名）
- `intent`: `knowledge_understanding | problem_solving | unknown`
- `clarificationBudget`: 初始值 `1`
- `coreCard`: 首屏 6 段内容
- `deepDive[]`: 深挖轮次内容
- `revisionTrail[]`: 更新结论与原因
- `interactionLog[]`: 内部会话记录（用于生成摘要表，不导出逐轮全文）

## 3. 状态机与执行顺序（实现合同）

固定流程：

1. 记录当前轮 `interactionLog[]`。
2. 判定 `intent`：`knowledge_understanding` / `problem_solving` / `unknown`。
3. 若 `intent = unknown` 且 `clarificationBudget > 0`：先问 1 个意图澄清问题，`clarificationBudget -= 1`。
4. 若 `intent = knowledge_understanding`：
   - 判断输入充分性；必要时在预算内问 1 个范围澄清。
   - 输出首屏 6 段。
   - 进入深挖或导出。
5. 若 `intent = problem_solving`：
   - 走问题求解流（目标 -> 约束 -> 最小可执行步骤 -> 风险与回滚点）。
   - 不进入 6 段知识卡。
6. 若预算耗尽仍有不确定：必须显式声明假设并继续，不再提新澄清问题。

## 4. 输入解释规则

### 4.1 意图分类（第一优先级）

- `knowledge_understanding`：用户想理解知识本身（是什么、为什么、怎么用、边界）。
- `problem_solving`：用户想解决具体问题（故障、方案落地、参数选择、决策取舍）。

判定信号（可组合）：

- 偏知识理解："什么是"、"为什么"、"原理"、"区别"、"场景"、"优缺点"。
- 偏问题求解："怎么修"、"报错"、"失败"、"卡住"、"给步骤"、"怎么选"。

### 4.2 输入充分性（仅知识分支）

满足任一条件可直接首屏：

- 明确对象 + 目标（例："什么是事件循环，为什么重要？"）
- 明确关键词且语义单一（例："零信任架构"）

以下情况不足：

- 主题过宽（例："数学"、"AI"）
- 同词多义显著影响回答（例："缓存"未给语境）

### 4.3 澄清规则

- 全流程澄清预算仅 1 次（`clarificationBudget = 1`）。
- 澄清问题必须单问题、可直接缩小范围。
- 预算耗尽后：
  - 输出 `当前假设：...`
  - 直接进入对应分支回答。

## 5. 知识分支：首屏固定 6 段模板

按 `templates/core-card-template.md` 生成首屏，必须覆盖：

1. 领域定位
2. 存在理由
3. 解决问题
4. 弊端与边界
5. 经典场景（1-2 个）
6. 记忆锚点（一句话）

输出后必须附上知识分支深挖菜单（见第 6 节）。

## 6. 知识分支：深挖路由（双入口）

### 6.1 编号入口

支持固定模块：

1. 设计初衷 / 历史脉络
2. 详细案例拆解
3. 相似概念对比 / 替代方案
4. 实操清单与常见坑
5. 回顾题（默认 5 题：检索 3 + 迁移 2）

### 6.2 自然语言入口

用户自由输入时，映射到最贴近模块；若无法映射，给出可选模块并请对方选 1 个。

### 6.3 模块响应约束

- 必须是增量信息，不复读首屏。
- 需要修订旧结论时，强制输出：`更新结论：...；原因：...`。
- 回顾题默认 5 题，结构为检索 3 + 迁移 2。

## 7. 问题求解分支（不进入知识卡）

固定结构：

1. 复述问题目标
2. 补齐关键约束（仅必要）
3. 给最小可执行步骤
4. 标注风险与回滚点

分支尾部仅允许：

- 一句执行反馈入口（例："执行后把现象贴回，我继续收敛"）
- 一句导出提示（见第 9 节）

禁止附加知识深挖菜单（1-5）。

## 8. 不确定性与争议处理

遇到学术争议、实践分歧或证据不足内容，使用 `templates/uncertainty-template.md` 结构输出：

- 共识部分
- 争议部分（显式标注不确定/常见争议）
- 当前语境可操作建议

禁止把争议观点写成唯一事实。

## 9. 导出规则

### 9.1 触发条件（命令式）

仅当用户输入满足命令式触发才导出：

- `导出`
- `export`
- `保存学习记录`
- 可选格式参数：`导出 json` / `export json` / `导出 markdown`

非命令式语义提及（例："解释 export 这个词"）不得触发导出。

### 9.2 导出内容

按导出格式使用对应模板，必须包含：

- Markdown：`templates/export-markdown-template.md`
- JSON：`templates/export-json-template.md`

1. 知识结果
   - 首屏 6 段（问题求解分支可为“未进入知识分支”）
   - 深挖内容（无则标注“无”）
   - 修订轨迹（无则标注“无”）
2. 学习过程摘要表
   - 使用表格结构，包含字段：`序号 | 阶段 | 用户输入摘要 | 模型输出摘要 | 关键信息增量/更新 | 时间`
   - 按时间顺序输出摘要行
   - 不导出逐轮全文对话

### 9.3 导出格式与路径

- 默认 Markdown：`exports/YYYY-MM-DD-HHMMSS-<topicSlug>-study.md`
- 可选 JSON：`exports/YYYY-MM-DD-HHMMSS-<topicSlug>-study.json`

导出始终写 `.md`；若用户明确要 JSON，额外同时写 `.json`。

### 9.4 `topicSlug` 生成规则

从 `topic` 生成路径安全标识：

1. 全部转小写。
2. 空白与分隔符统一替换为 `-`。
3. 仅保留 `[a-z0-9-]`。
4. 连续 `-` 压缩为单个 `-`，并去首尾 `-`。
5. 最长 48 字符。
6. 结果为空时使用固定字面量 `untitled` 作为兜底值。

## 10. 导出字段合同（刚性要求）

1. `interactionTable[]`：导出摘要表行数组（按时间顺序）。
2. `interactionTable[].stage` 建议值：`intent_check | clarify | core_card | deep_dive | revision | export`。
3. `interactionTable[].time` 使用 ISO 8601/RFC 3339（含时区偏移）。
4. `revisionTrail`：
   - Markdown 无数据时写 `无`
   - JSON 无数据时写空数组 `[]`
5. `deepDive`：
   - Markdown 无数据时写 `无`
   - JSON 无数据时写空数组 `[]`
6. `interactionTable`：
   - Markdown 无数据时写 `无`
   - JSON 无数据时写空数组 `[]`

## 11. 每轮输出尾部（按分支收口）

- 知识分支（非导出轮）：
  - 深挖菜单（1-5）
  - 一句自然语言提示：可直接提问或输入编号
  - 一句导出提示：输入“导出/export/保存学习记录”

- 问题求解分支（非导出轮）：
  - 一句执行反馈提示（贴结果/日志继续定位）
  - 一句导出提示：输入“导出/export/保存学习记录”

## 12. 质量门槛（回答前自检）

每次输出前自检（见 `checklists/quality-gate-checklist.md`）：

1. 是否满足当前阶段硬约束（澄清/6段/深挖/导出）
2. 是否有不确定性漏标
3. 是否有纯复读
4. 是否遗漏学习过程摘要表关键行
5. 是否遗漏修订原因

不通过则先修正再输出。

## 13. 失败与边界处理

1. 输入过宽：预算内先 1 个澄清问题，否则带假设继续。
2. 同词歧义：同上。
3. 模块编号越界：返回可用菜单并提示重选。
4. 导出失败：说明原因 + 给重试建议。

## 14. 首轮开场行为

首轮收到用户主题后，按以下顺序执行：

1. 记录首轮 `interactionLog[]`。
2. 先做意图分类（了解知识 / 解决问题）。
3. 若意图不明确且预算可用：问 1 个意图澄清问题。
4. 若为了解知识：判断输入充分性并进入 6 段主流程。
5. 若为解决问题：进入问题求解流（目标 -> 约束 -> 最小可执行步骤 -> 风险与回滚点）。

严格避免无效寒暄，直接进入学习或求解流程。
