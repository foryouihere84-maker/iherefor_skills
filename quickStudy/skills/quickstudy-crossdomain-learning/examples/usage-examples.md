# quickStudy 跨领域速学 Skill 使用示例

> 运行入口说明见：[README-RUN.md](../README-RUN.md)

## 示例 0：先判意图

用户输入：`Redis 一直超时，怎么处理？`

系统行为：
1. 判定为“解决问题”意图。
2. 不触发 6 段知识卡。
3. 输出问题求解流（目标 -> 约束 -> 最小可执行步骤 -> 风险与回滚点）。
4. 尾部不出现 `1~5` 知识深挖菜单，只保留执行反馈提示 + 导出提示。

## 示例 1：输入充分（知识理解）

用户输入：`零信任架构`

系统行为：
1. 判定为“了解知识”意图。
2. 直接输出首屏 6 段。
3. 给出深挖菜单（1-5）。
4. 支持用户输入 `2` 或自然语言追问。

## 示例 2：输入不足 + 澄清预算

用户输入：`数学`

系统行为：
1. 判定为“了解知识”意图，但输入范围过宽。
2. 消耗 1 次澄清预算，问 1 个范围收敛问题。
3. 若用户继续模糊，预算已耗尽，系统必须输出：`当前假设：...` 并继续回答，不再追问。

## 示例 3：导出触发（命令式）

用户输入：`导出 json`

系统行为：
1. 触发导出流程。
2. 汇总知识结果（首屏 + 深挖 + 修订轨迹）。
3. 汇总学习过程摘要表（非全量对话，表格化）。
4. 输出 JSON 与 Markdown 文件路径：`exports/YYYY-MM-DD-HHMMSS-<topicSlug>-study.json` 与 `exports/YYYY-MM-DD-HHMMSS-<topicSlug>-study.md`。

## 示例 4：非触发边界（语义提及）

用户输入：`解释 export 这个词是什么意思？`

系统行为：
1. 不触发导出流程。
2. 把该输入当作普通知识问题处理。

## 示例 5：topicSlug 清洗

原始主题：`Redis 超时 / 连接池?`

系统行为：
1. 生成 `topicSlug`（按规则小写、清洗非法字符、压缩连接符、长度限制）。
2. 路径使用 slug，不直接用原始主题。
3. 导出路径示例：`exports/2026-07-21-142530-redis-study.md`。
