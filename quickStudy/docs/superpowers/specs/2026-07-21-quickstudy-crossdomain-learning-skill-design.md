# quickStudy 跨领域知识速学/回顾 Skill 设计规格

- 日期：2026-07-21
- 项目：quickStudy
- 状态：设计已确认（待用户最终审阅）

## 1. 背景与目标

目标：构建一个跨领域通用学习 Skill。用户输入可以是一个问题、关键词、或短句，系统快速输出结构化知识卡，帮助用户在短时间内掌握“是什么、解决什么、何时用”，并支持深挖与导出完整学习记录。

本设计强调“按任务分段”，不是“按字数分段”。每个段落有明确职责，优先可理解性与可回顾性。

## 2. 范围（In Scope）与非范围（Out of Scope）

### In Scope

1. 自由输入支持：问题/关键词/短句。
2. 首屏固定 6 段知识卡（允许轻微重排，不允许缺段）。
3. 深挖双入口：编号菜单 + 自然语言追问。
4. 导出功能：导出知识结果与交互问答过程。
5. 争议信息处理：明确标注“不确定/常见争议”，不给伪确定结论。
6. 回顾题生成：每主题默认 5 题（检索 + 迁移）。

### Out of Scope（首版不做）

1. 第三方知识库接入（如外部向量库、私有文档系统）。
2. 用户账户体系、权限体系、云端同步。
3. 多语言本地化细分策略（先默认中文输出，输入语言可后续扩展）。
4. 自动评分引擎的复杂统计面板（仅保留基础通过率统计口径）。

## 3. 关键设计原则

1. 任务驱动分层：先给短而完整的任务段落，再按需深入。
2. 先理解后扩展：首屏确保全景，深挖避免复读。
3. 不确定性可见：争议观点显式标注，不假装确定。
4. 一致性可追踪：新信息推翻旧结论时，必须标注“更新结论 + 原因”。
5. 可导出可复盘：学习结果和问答过程都可落盘。

## 4. 方案对比与选型

### 方案 A：一次全量输出
- 优点：一步到位。
- 缺点：噪音高，速览价值下降。

### 方案 B：纯分阶段交互
- 优点：按需深入，信息负担小。
- 缺点：轮次多，首屏全貌不足。

### 方案 C：速览 + 最小扩展
- 优点：折中。
- 缺点：扩展边界不稳定。

### 方案 D（选中）：任务驱动分层卡
- 优点：兼顾“快速理解 + 深入探索”；每段职责清晰；最贴合目标。
- 结论：采用 D。

## 5. 用户交互流程

1. 用户输入问题/关键词/短句。
2. 系统判断输入充分性：
   - 充分：直接输出首屏 6 段。
   - 不充分：先提出 1 个澄清问题，补齐后输出 6 段。
3. 输出深挖入口：
   - 编号菜单（模块化）
   - 自然语言追问（自由化）
4. 每轮深挖后回到分叉点：继续深挖 / 导出记录。
5. 用户触发导出后，生成导出文件并返回路径与摘要。

## 6. 首屏固定 6 段规范

每次首屏必须覆盖以下 6 段（可轻微重排）：

1. 领域定位：这个知识属于哪类主题。
2. 存在理由：为何会被提出、要解决什么历史/实践痛点。
3. 解决问题：核心机制与主要收益。
4. 弊端与边界：代价、风险、何时不适用。
5. 经典场景：1-2 个高频使用场景。
6. 记忆锚点：一句话带走。

## 7. 深挖模块设计

默认模块集合：

1. 设计初衷/历史脉络
2. 详细案例拆解
3. 相似概念对比/替代方案
4. 实操清单与常见坑
5. 回顾题（默认 5 题：检索题 + 迁移题）

触发方式：

- 菜单编号触发（例如输入 `2` 进入案例模块）
- 自然语言触发（例如“给我一个反例场景”）

约束：

- 模块回答必须增量，不重复首屏。
- 如涉及旧结论修正，必须输出“更新结论：...；原因：...”。

## 8. 不确定性与争议处理规范

1. 对存在学术争议、流派分歧、或证据不足的知识点：
   - 必须显式标注“该点存在争议/不确定”。
2. 禁止输出口吻：
   - 禁止把争议观点说成唯一确定事实。
3. 推荐输出模板：
   - 共识部分
   - 争议部分
   - 当前语境下可操作建议

## 9. 导出功能设计

### 9.1 触发方式

- 关键词触发：`导出` / `export` / `保存学习记录`。

### 9.2 导出内容

导出文件必须包含两大块：

1. 知识结果
   - 首屏 6 段
   - 后续深挖内容
   - 若有更新结论，需保留修订轨迹

2. 交互过程
   - 用户每轮问题
   - 模型每轮回应
   - 保持时间顺序

### 9.3 导出格式

- 默认：Markdown（可读、可编辑）
- 可选：JSON（结构化消费）

建议文件路径：

- `exports/YYYY-MM-DD-<topic>-study.md`
- `exports/YYYY-MM-DD-<topic>-study.json`

## 10. 组件边界（逻辑分层）

1. InputInterpreter：输入类型识别与充分性判断。
2. CoreCardGenerator：首屏 6 段生成。
3. DeepDiveRouter：菜单与自然语言映射到深挖模块。
4. ConsistencyGuard：去重、冲突检测、更新结论标注。
5. UncertaintyMarker：争议/不确定标签规范化。
6. ExportBuilder：知识结果 + 问答过程组装导出。

每个组件保持单一职责，便于后续拆分实现与测试。

## 11. 数据流

1. 原始输入进入 InputInterpreter。
2. 若需澄清，先生成单问题补充，再回流 InputInterpreter。
3. 生成 CoreCard（6 段）。
4. 用户触发 DeepDiveRouter 进入对应模块。
5. 每次输出经 ConsistencyGuard + UncertaintyMarker 处理。
6. 触发导出时由 ExportBuilder 拉取会话上下文并落盘。

## 12. 错误处理与边界条件

1. 输入过宽（如“数学”）：先缩小范围再输出核心卡。
2. 输入歧义（同词多义）：先给最小澄清问题。
3. 导出失败（路径/权限问题）：返回失败原因 + 重试建议。
4. 模块请求越界（未知编号）：回退到可用菜单并提示重选。

## 13. 测试与验收（严格发布门槛）

## 13.1 功能门槛（必须 100% 通过）

1. 自由输入解析通过。
2. 首屏 6 段齐全。
3. 深挖双入口可连续多轮。
4. 导出内容完整（知识结果 + 全量问答过程）。
5. 输入不足时先澄清再回答。

## 13.2 质量门槛（严格阈值）

1. 2 分钟复述测试：20 个主题，成功率 >= 90%。
2. 回顾题测试：每主题 5 题，正确率 >= 80%。
3. 深挖去重质量：不可出现纯复读。
4. 争议处理覆盖：争议主题 100% 标注不确定性。
5. 结论修订可追踪：更新结论必须带原因。

## 13.3 稳定性门槛

1. 黄金样例集：至少 50 条输入，改动后全量回归。
2. P0/P1 问题为 0 才可发布。
3. 随机抽检 20 份导出文件，字段完整率 100%。

## 14. 验收失败条件（任一命中即拦截）

1. 漏任一核心段。
2. 导出缺任一对话轮次。
3. 争议主题未标注不确定性。
4. 深挖明显复读且无新增信息。
