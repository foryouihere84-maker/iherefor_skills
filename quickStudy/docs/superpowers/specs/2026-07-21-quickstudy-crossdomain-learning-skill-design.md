# quickStudy 跨领域知识速学/回顾 Skill 设计规格

- 日期：2026-07-21
- 项目：quickStudy
- 状态：设计已确认（规范修订版）
- 规范基线：`quickStudy/skills/quickstudy-crossdomain-learning/SKILL.md`（本规格与实现冲突时，以 SKILL.md 为准）

## 1. 背景与目标

目标：构建一个跨领域通用学习 Skill。用户输入可以是一个问题、关键词、或短句，系统快速输出结构化知识卡，帮助用户在短时间内掌握“是什么、解决什么、何时用”，并支持深挖与导出完整学习记录。

本设计强调“按任务分段”，不是“按字数分段”。每个段落有明确职责，优先可理解性与可回顾性。

## 2. 范围（In Scope）与非范围（Out of Scope）

### In Scope

1. 自由输入支持：问题/关键词/短句。
2. 首屏固定 6 段知识卡（允许轻微重排，不允许缺段）。
3. 深挖双入口：编号菜单 + 自然语言追问（仅知识分支）。
4. 导出功能：导出知识结果与学习过程摘要表（表格，非全量对话）。
5. 争议信息处理：明确标注“不确定/常见争议”，不给伪确定结论。
6. 回顾题生成：每主题默认 5 题（检索 3 + 迁移 2）。
7. 问题求解分支：目标 -> 约束 -> 最小可执行步骤 -> 风险与回滚点，不进入知识卡。

### Out of Scope（首版不做）

1. 第三方知识库接入（如外部向量库、私有文档系统）。
2. 用户账户体系、权限体系、云端同步。
3. 多语言本地化细分策略（先默认中文输出，输入语言可后续扩展）。
4. 自动评分引擎的复杂统计面板（仅保留基础通过率统计口径）。

## 3. 关键设计原则

1. 任务驱动分层：先给短而完整的任务段落，再按需深入。
2. 先理解后扩展：首屏确保全景，深挖避免复读。
3. 不确定性可见：争议观点显式标注，不假装确定。
4. 一致性可追踪：新信息推翻旧结论时，必须标注“更新结论 + 原因”。
5. 可导出可复盘：学习结果和学习过程摘要表都可落盘。
6. 分支收口隔离：知识分支和问题求解分支尾部行为不可混用。

## 4. 方案对比与选型

### 方案 A：一次全量输出
- 优点：一步到位。
- 缺点：噪音高，速览价值下降。

### 方案 B：纯分阶段交互
- 优点：按需深入，信息负担小。
- 缺点：轮次多，首屏全貌不足。

### 方案 C：速览 + 最小扩展
- 优点：折中。
- 缺点：扩展边界不稳定。

### 方案 D（选中）：任务驱动分层卡 + 意图门控
- 优点：兼顾“快速理解 + 深入探索”；每段职责清晰；问题求解场景不被知识流污染。
- 结论：采用 D。

## 5. 用户交互流程（与 SKILL.md 对齐）

1. 用户输入问题/关键词/短句。
2. 系统先判意图：
   - `knowledge_understanding`
   - `problem_solving`
   - `unknown`
3. 当 `unknown` 且澄清预算可用（`clarificationBudget = 1`）：问 1 个澄清问题。
4. 分支执行：
   - 知识分支：输入充分性判断 -> 首屏 6 段 -> 深挖/导出。
   - 问题求解分支：目标 -> 约束 -> 最小可执行步骤 -> 风险与回滚点。
5. 导出触发（命令式）后，生成导出文件并返回路径与摘要。
6. 澄清预算耗尽仍有不确定时，必须声明当前假设并继续。

## 6. 首屏固定 6 段规范（知识分支）

每次首屏必须覆盖以下 6 段（可轻微重排）：

1. 领域定位：这个知识属于哪类主题。
2. 存在理由：为何会被提出、要解决什么历史/实践痛点。
3. 解决问题：核心机制与主要收益。
4. 弊端与边界：代价、风险、何时不适用。
5. 经典场景：1-2 个高频使用场景。
6. 记忆锚点：一句话带走。

## 7. 深挖模块设计（仅知识分支）

默认模块集合：

1. 设计初衷/历史脉络
2. 详细案例拆解
3. 相似概念对比/替代方案
4. 实操清单与常见坑
5. 回顾题（默认 5 题：检索题 + 迁移题）

触发方式：

- 菜单编号触发（例如输入 `2` 进入案例模块）
- 自然语言触发（例如“给我一个反例场景”）

约束：

- 模块回答必须增量，不重复首屏。
- 如涉及旧结论修正，必须输出“更新结论：...；原因：...”。

## 8. 不确定性与争议处理规范

1. 对存在学术争议、流派分歧、或证据不足的知识点：
   - 必须显式标注“该点存在争议/不确定”。
2. 禁止输出口吻：
   - 禁止把争议观点说成唯一确定事实。
3. 推荐输出模板：
   - 共识部分
   - 争议部分
   - 当前语境下可操作建议

## 9. 导出功能设计

### 9.1 触发方式（命令式）

仅命令式输入触发导出：

- `导出`
- `export`
- `保存学习记录`
- 可选格式参数：`导出 json` / `export json` / `导出 markdown`

语义提及不触发（例：`解释 export 这个词`）。

### 9.2 导出内容

导出文件必须包含两大块：

1. 知识结果
   - 首屏 6 段
   - 后续深挖内容
   - 若有更新结论，需保留修订轨迹

2. 学习过程摘要表
   - 关键阶段摘要（意图判定/澄清/首屏/深挖/修订/导出）
   - 用户输入摘要与模型输出摘要
   - 关键信息增量/更新
   - 时间顺序（按摘要行）

### 9.3 导出格式

- 默认：Markdown（可读、可编辑）
- 可选：JSON（结构化消费）

导出行为：始终写入 Markdown；若用户明确请求 JSON（`导出 json` / `export json`），额外同时写入 JSON。

建议文件路径：

- `exports/YYYY-MM-DD-HHMMSS-<topicSlug>-study.md`
- `exports/YYYY-MM-DD-HHMMSS-<topicSlug>-study.json`

### 9.4 topicSlug 规则

`topicSlug` 用于路径安全文件名，规则：

1. 小写化
2. 空白/分隔符转 `-`
3. 仅保留 `[a-z0-9-]`
4. 压缩连续 `-` 并去首尾 `-`
5. 长度上限 48
6. 结果为空时兜底固定字面量 `untitled`（不是原始 `topic` 文本）

## 10. 组件边界（逻辑分层）

1. InputInterpreter：输入类型识别与意图判定。
2. CoreCardGenerator：首屏 6 段生成。
3. DeepDiveRouter：知识分支菜单与自然语言映射到深挖模块。
4. ProblemSolver：问题求解分支生成最小可执行路径。
5. ConsistencyGuard：去重、冲突检测、更新结论标注。
6. UncertaintyMarker：争议/不确定标签规范化。
7. ExportBuilder：知识结果 + 学习过程摘要表组装导出。

每个组件保持单一职责，便于后续拆分实现与测试。

## 11. 数据流

1. 原始输入进入 InputInterpreter。
2. 若需澄清，先生成单问题补充，再回流 InputInterpreter。
3. 生成 CoreCard（6 段）。
4. 用户触发 DeepDiveRouter 进入对应模块。
5. 每次输出经 ConsistencyGuard + UncertaintyMarker 处理。
6. 触发导出时由 ExportBuilder 拉取会话上下文并落盘。

## 12. 错误处理与边界条件

1. 输入过宽（如“数学”）：先缩小范围再输出核心卡。
2. 输入歧义（同词多义）：先给最小澄清问题。
3. 导出失败（路径/权限问题）：返回失败原因 + 重试建议。
4. 模块请求越界（未知编号）：回退到可用菜单并提示重选。

## 13. 测试与验收（严格发布门槛）

## 13.1 功能门槛（必须 100% 通过）

1. 自由输入解析通过。
2. 知识分支首屏 6 段齐全。
3. 深挖双入口可连续多轮。
4. 导出内容完整（知识结果 + 学习过程摘要表）。
5. 输入不足时先澄清再回答。

## 13.2 质量门槛（严格阈值）

1. 2 分钟复述测试：20 个主题，成功率 >= 90%。
2. 回顾题测试：每主题 5 题，正确率 >= 80%。
3. 深挖去重质量：不可出现纯复读。
4. 争议处理覆盖：争议主题 100% 标注不确定性。
5. 结论修订可追踪：更新结论必须带原因。

## 13.3 稳定性门槛

1. 黄金样例集：至少 50 条输入，改动后全量回归。
2. P0/P1 问题为 0 才可发布。
3. 随机抽检 20 份导出文件，字段完整率 100%。

## 14. 验收失败条件（任一命中即拦截）

1. 漏任一核心段。
2. 导出摘要表缺关键字段或关键阶段。
3. 争议主题未标注不确定性。
4. 深挖明显复读且无新增信息。
